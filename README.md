# راهنمای استقرار و نگهداری Jahannama

این مستند نحوه راه‌اندازی، ساختار استقرار، به‌روزرسانی و نگهداری وب‌سایت Jahannama روی سرور لینوکسی را توضیح می‌دهد.

هدف این راهنما آن است که در آینده بتوان پروژه را بدون وابستگی به حافظه افراد، به‌روزرسانی و عیب‌یابی کرد و در صورت نیاز، زیرساخت آن را توسعه داد.

## ۱. معماری فعلی

وب‌سایت با Django پیاده‌سازی شده و برای اجرا در محیط عملیاتی از Gunicorn و Nginx استفاده می‌کند.

مسیر دریافت درخواست‌ها به این شکل است:

```text
                کاربر / مرورگر
                       |
                       | HTTPS :443
                       v
                Nginx Reverse Proxy
                 /       |       \
                /        |        \
           /static/   /media/    سایر مسیرها
              |          |           |
              v          v           v
          staticfiles   media     Gunicorn
                                     |
                                  127.0.0.1:8000
                                     |
                                     v
                               Django / WSGI
                                     |
                                     v
                                  SQLite
```

### اجزای اصلی

| جزء                 | کاربرد                                                                        |
| ------------------- | ----------------------------------------------------------------------------- |
| Ubuntu Server 24.04 | سیستم‌عامل سرور                                                               |
| Python و محیط مجازی | اجرای برنامه و وابستگی‌ها                                                     |
| Django 5.2          | فریم‌ورک اصلی وب                                                              |
| Gunicorn            | اجرای برنامه Django در محیط عملیاتی                                           |
| systemd             | اجرا و راه‌اندازی مجدد خودکار سرویس                                           |
| Nginx               | دریافت درخواست‌ها، ارائه فایل‌های استاتیک و تصاویر و هدایت درخواست‌های برنامه |
| SQLite              | پایگاه داده فعلی                                                              |
| Let's Encrypt       | صدور گواهی SSL رایگان                                                         |
| Certbot             | مدیریت گواهی و تمدید خودکار آن                                                |
| Git و GitHub        | دریافت نسخه‌های جدید پروژه                                                    |

در وضعیت فعلی، برنامه مستقیماً روی سیستم‌عامل سرور اجرا می‌شود و از Docker استفاده نمی‌کند. همچنین پایگاه داده فعلی SQLite است و PostgreSQL نصب یا پیکربندی‌شده فرض نشده است.

## ۲. مشخصات سرور و دامنه

اطلاعات عملیاتی فعلی:

| مورد                          | مقدار                                       |
| ----------------------------- | ------------------------------------------- |
| سیستم‌عامل                    | Ubuntu 24.04 LTS                            |
| آدرس پروژه روی سرور           | `/opt/Jahannama`                            |
| مخزن Git                      | `git@github.com:mahdismahdis/Jahannama.git` |
| شاخه اصلی                     | `main`                                      |
| دامنه اصلی                    | `jahannama-food.com`                        |
| دامنه جایگزین                 | `www.jahannama-food.com`                    |
| پورت داخلی Gunicorn           | `127.0.0.1:8000`                            |
| فایل متغیرهای محیطی           | `/etc/jahannama.env`                        |
| سرویس systemd                 | `jahannama.service`                         |
| تنظیمات Nginx                 | `/etc/nginx/sites-available/jahannama`      |
| فایل‌های استاتیک جمع‌آوری‌شده | `/opt/Jahannama/staticfiles`                |
| فایل‌های رسانه‌ای             | `/opt/Jahannama/media`                      |
| پایگاه داده                   | `/opt/Jahannama/db.sqlite3`                 |

برای اتصال SSH به سرور از پورت `9011` استفاده می‌شود:

```bash
ssh -p 9011 root@SERVER_IP
```

به‌جای `SERVER_IP` باید آدرس IP واقعی سرور قرار بگیرد.

## ۳. ساختار فایل‌های استقرار

ساختار مرتبط با اجرای برنامه روی سرور به این صورت است:

```text
/opt/Jahannama/
├── .venv/
├── manage.py
├── myapp/
│   ├── static/
│   └── templates/
├── mysite/
│   ├── settings.py
│   └── wsgi.py
├── db.sqlite3
├── media/
└── staticfiles/

/etc/
├── jahannama.env
├── systemd/system/
│   └── jahannama.service
└── nginx/
    └── sites-available/
        └── jahannama
```

**توجه:** فایل `staticfiles/` خروجی جمع‌آوری فایل‌های استاتیک Django است. فایل‌های اصلی CSS و سایر منابع استاتیک در کد پروژه قرار دارند. هنگام تغییر فایل‌های استاتیک، باید دستور `collectstatic` اجرا شود.

فایل‌های رسانه‌ای کاربران و پایگاه داده باید در فرآیند به‌روزرسانی کد حفظ شوند.

## ۴. نحوه اجرای برنامه

### ۴.۱. محیط مجازی Python

وابستگی‌های برنامه در محیط مجازی زیر نصب شده‌اند:

```text
/opt/Jahannama/.venv
```

برای فعال‌سازی محیط مجازی:

```bash
cd /opt/Jahannama
source .venv/bin/activate
```

برای بررسی نسخه Django:

```bash
python -m django --version
```

برای نصب وابستگی‌های جدید، ابتدا فایل `requirements.txt` را بررسی کنید. در صورت نیاز به نصب وابستگی‌ها:

```bash
pip install -r requirements.txt
```

بهتر است نسخه وابستگی‌ها و فایل `requirements.txt` در مخزن Git کنترل شوند تا استقرار در محیط‌های دیگر نیز قابل تکرار باشد.

### ۴.۲. اجرای برنامه با Gunicorn

Gunicorn برنامه Django را با استفاده از ماژول WSGI اجرا می‌کند:

```text
mysite.wsgi:application
```

Gunicorn فقط روی آدرس محلی زیر گوش می‌دهد:

```text
127.0.0.1:8000
```

بنابراین پورت برنامه مستقیماً برای دسترسی عمومی اینترنت باز نشده است و درخواست‌های عمومی از طریق Nginx به آن منتقل می‌شوند.

### ۴.۳. مدیریت سرویس با systemd

فایل سرویس در مسیر زیر قرار دارد:

```text
/etc/systemd/system/jahannama.service
```

این سرویس با کاربر سیستمی `jahannama` و گروه `www-data` اجرا می‌شود. تنظیمات مهم آن شامل موارد زیر است:

* مسیر اجرای پروژه: `/opt/Jahannama`
* فایل متغیرهای محیطی: `/etc/jahannama.env`
* تعداد Workerهای Gunicorn: دو عدد
* آدرس داخلی: `127.0.0.1:8000`
* راه‌اندازی مجدد سرویس در صورت شکست اجرا

برای مشاهده وضعیت:

```bash
systemctl status jahannama --no-pager
```

برای راه‌اندازی مجدد:

```bash
systemctl restart jahannama
```

برای فعال بودن سرویس پس از راه‌اندازی مجدد سرور:

```bash
systemctl is-enabled jahannama
```

## ۵. تنظیم متغیرهای محیطی

تنظیمات حساس و برخی تنظیمات محیط عملیاتی خارج از مخزن Git نگهداری می‌شوند:

```text
/etc/jahannama.env
```

این فایل شامل مقادیری مانند موارد زیر است:

```dotenv
DJANGO_SECRET_KEY=<secret-value>
DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=jahannama-food.com,www.jahannama-food.com,SERVER_IP,localhost,127.0.0.1
DJANGO_CSRF_TRUSTED_ORIGINS=https://jahannama-food.com,https://www.jahannama-food.com
```

مقدار `SERVER_IP` در نمونه بالا صرفاً جای‌نگهدار است و باید با IP واقعی سرور جایگزین شود.

### نکات مهم

* مقدار واقعی `DJANGO_SECRET_KEY` محرمانه است و نباید در README یا مخزن عمومی قرار گیرد.
* فایل محیطی نباید به Git اضافه شود.
* دسترسی فایل باید محدود باشد؛ در استقرار فعلی مجوز فایل برای مالک ریشه و بدون دسترسی عمومی تنظیم شده است.
* `DJANGO_DEBUG` در محیط عملیاتی باید `False` باشد.
* دامنه‌ها و مبدأهای مجاز باید متناسب با دامنه‌های واقعی سایت تنظیم شوند.

برای بررسی تنظیمات Django:

```bash
cd /opt/Jahannama
source .venv/bin/activate

set -a
source /etc/jahannama.env
set +a

python manage.py check
python manage.py check --deploy
```

فرمان دوم هشدارهای امنیتی مرتبط با استقرار را نیز بررسی می‌کند. هشدارها باید بررسی شوند؛ لزوماً همه آن‌ها خطای اجرایی نیستند.

## ۶. تنظیم Nginx

فایل تنظیمات سایت در مسیر زیر قرار دارد:

```text
/etc/nginx/sites-available/jahannama
```

این فایل به مسیر `sites-enabled` لینک شده است و Nginx از آن برای سرویس‌دهی استفاده می‌کند.

وظایف اصلی Nginx عبارت‌اند از:

1. دریافت درخواست‌های HTTP و HTTPS.
2. هدایت درخواست‌های HTTP به HTTPS.
3. ارائه مستقیم فایل‌های استاتیک از مسیر `/static/`.
4. ارائه فایل‌های رسانه‌ای از مسیر `/media/`.
5. انتقال درخواست‌های سایر مسیرها به Gunicorn.
6. ارسال اطلاعات میزبان، IP مبدأ و پروتکل درخواست به برنامه.

برای بررسی صحت تنظیمات:

```bash
nginx -t
```

برای بارگذاری مجدد تنظیمات:

```bash
systemctl reload nginx
```

پس از تغییر تنظیمات Nginx، ابتدا `nginx -t` را اجرا کنید. اگر تنظیمات معتبر نبودند، سرویس را Reload نکنید تا ابتدا خطا برطرف شود.

## ۷. گواهی SSL و HTTPS

برای دامنه‌های زیر گواهی Let's Encrypt صادر شده است:

* `jahannama-food.com`
* `www.jahannama-food.com`

مسیرهای گواهی:

```text
/etc/letsencrypt/live/jahannama-food.com/fullchain.pem
/etc/letsencrypt/live/jahannama-food.com/privkey.pem
```

گواهی در زمان راه‌اندازی معتبر بوده و تمدید خودکار Certbot نیز با موفقیت آزمایش شده است.

برای بررسی گواهی:

```bash
certbot certificates
```

برای آزمایش تمدید:

```bash
certbot renew --dry-run
```

### نکته مربوط به Cloudflare

اگر DNS دامنه از Cloudflare عبور می‌کند و Proxy آن فعال است، حالت رمزنگاری ارتباط با سرور مبدأ باید روی **Full (strict)** باشد. حالت Flexible ممکن است در کنار هدایت اجباری HTTPS در Nginx یا Django باعث حلقه انتقال شود.

تنظیمات فعلی Nginx باید با تنظیمات HTTPS برنامه هماهنگ بمانند.

## ۸. به‌روزرسانی نسخه سایت

روش پیشنهادی به‌روزرسانی، دریافت کد از شاخه `main` و سپس بررسی و راه‌اندازی مجدد برنامه است.

### مرحله اول: ورود به پروژه و بررسی تغییرات محلی

```bash
cd /opt/Jahannama

git status
git branch --show-current
```

اگر فایل محلی تغییر کرده است، قبل از دریافت نسخه جدید مشخص کنید که تغییر باید حفظ، ثبت یا با نسخه مخزن ادغام شود. تغییرات را بدون بررسی حذف نکنید.

### مرحله دوم: دریافت نسخه جدید

```bash
git pull --ff-only origin main
```

گزینه `--ff-only` از ایجاد Merge Commit ناخواسته هنگام دریافت نسخه جلوگیری می‌کند.

### مرحله سوم: فعال‌سازی محیط و بررسی تنظیمات

```bash
source .venv/bin/activate

set -a
source /etc/jahannama.env
set +a

python manage.py check
```

اگر نسخه جدید شامل تغییر مدل‌های Django است، قبل از ادامه، Migrationهای پروژه را بررسی کنید:

```bash
python manage.py showmigrations
```

اگر Migration جدید وجود دارد و برای نسخه جدید لازم است، پس از تهیه نسخه پشتیبان مناسب از پایگاه داده اجرا کنید:

```bash
python manage.py migrate
```

اگر تغییری در مدل‌ها یا Migrationها وجود ندارد، اجرای Migration صرفاً به دلیل به‌روزرسانی کد ضروری نیست.

### مرحله چهارم: جمع‌آوری فایل‌های استاتیک

```bash
python manage.py collectstatic --noinput
```

این دستور فایل‌های استاتیک برنامه را در مسیر پیکربندی‌شده، یعنی `staticfiles/`، جمع‌آوری می‌کند.

### مرحله پنجم: بررسی و راه‌اندازی مجدد

```bash
python manage.py check --deploy

nginx -t
systemctl restart jahannama
systemctl status jahannama --no-pager
```

اگر تنظیمات Nginx تغییر نکرده است، Reload آن معمولاً لازم نیست. اگر تنظیمات تغییر کرده‌اند، پس از موفقیت `nginx -t`، آن را Reload کنید.

### مرحله ششم: تست سایت

```bash
curl -I https://jahannama-food.com
curl -I https://www.jahannama-food.com
curl -I http://jahannama-food.com
```

در پیکربندی فعلی، انتظار می‌رود:

* درخواست HTTPS به دامنه اصلی پاسخ معتبر دریافت کند.
* مسیر فارسی سایت، مانند `/fa/`، با توجه به تنظیمات برنامه قابل دسترسی باشد.
* درخواست HTTP به HTTPS منتقل شود.

کد `301` برای انتقال دائمی HTTP به HTTPS و کد `302` برای انتقال موقت به مسیر دیگری مانند `/fa/` می‌تواند طبیعی باشد. برای اطمینان از سالم بودن سایت، فقط به کد وضعیت اکتفا نکنید؛ صفحه و فایل‌های استاتیک را نیز بررسی کنید.

## ۹. بررسی وضعیت و عیب‌یابی

### مشاهده گزارش سرویس Django و Gunicorn

برای مشاهده گزارش‌های اخیر:

```bash
journalctl -u jahannama -n 100 --no-pager
```

برای دنبال کردن گزارش‌ها به‌صورت زنده:

```bash
journalctl -u jahannama -f
```

برای گزارش‌های خطا در Nginx:

```bash
tail -n 100 /var/log/nginx/error.log
```

### بررسی پاسخ Gunicorn

```bash
curl -I http://127.0.0.1:8000
```

اگر برنامه به `/fa/` هدایت کند و پاسخ `302` برگرداند، این رفتار با مسیریابی فعلی سایت سازگار است.

### بررسی دسترسی پورت‌ها

```bash
ss -lntp
```

Gunicorn باید روی `127.0.0.1:8000` در دسترس باشد. Nginx نیز باید روی پورت‌های موردنیاز HTTP و HTTPS گوش بدهد.

### راهنمای سریع عیب‌یابی

| مشکل                         | بررسی اولیه                                                       |
| ---------------------------- | ----------------------------------------------------------------- |
| خطای 502                     | وضعیت سرویس Gunicorn، گزارش `jahannama.service` و اتصال پورت 8000 |
| خطای 400 یا `DisallowedHost` | مقدار `DJANGO_ALLOWED_HOSTS`                                      |
| خطای CSRF                    | دامنه و پروتکل در `DJANGO_CSRF_TRUSTED_ORIGINS` و تنظیمات HTTPS   |
| نمایش ندادن CSS              | اجرای `collectstatic`، تنظیم `location /static/` و کش مرورگر      |
| نمایش ندادن تصاویر           | وجود فایل‌ها در `media/` و دسترسی Nginx به آن‌ها                  |
| خطای پایگاه داده             | وجود فایل SQLite، مالکیت و مجوزهای فایل و پوشه                    |
| اجرا نشدن سرویس              | `systemctl status` و `journalctl`                                 |
| خطای گواهی                   | بررسی دامنه‌ها، تاریخ اعتبار و وضعیت تمدید Certbot                |

## ۱۰. پشتیبان‌گیری و بازیابی

پشتیبان‌گیری باید دست‌کم سه بخش را پوشش دهد:

1. پایگاه داده SQLite در `db.sqlite3`.
2. فایل‌های رسانه‌ای در `media/`.
3. فایل‌های تنظیمات عملیاتی موردنیاز برای بازیابی، با حفظ محرمانگی مقادیر حساس.

کد پروژه از طریق GitHub قابل دریافت مجدد است، اما **Git جایگزین پشتیبان پایگاه داده و فایل‌های رسانه‌ای نیست**.

### نکات مربوط به SQLite

برای تهیه پشتیبان مطمئن از SQLite، از ابزار `sqlite3` و دستور `.backup` استفاده کنید یا برنامه را در یک بازه کنترل‌شده متوقف کنید و نسخه‌ای سازگار از فایل پایگاه داده بگیرید. کپی ساده فایل SQLite در حین نوشتن فعال ممکن است برای همه شرایط، پشتیبان سازگاری ایجاد نکند.

نمونه پشتیبان‌گیری با ابزار SQLite:

```bash
sqlite3 /opt/Jahannama/db.sqlite3 \
  ".backup '/PATH/TO/BACKUP/jahannama-db.sqlite3'"
```

مسیر `/PATH/TO/BACKUP/` یک نمونه است؛ آن را با مسیر واقعی محل پشتیبان‌گیری جایگزین کنید. ابتدا مطمئن شوید ابزار `sqlite3` نصب است و پوشه مقصد وجود دارد.

برای پشتیبان‌گیری از رسانه‌ها، می‌توان از `tar` استفاده کرد:

```bash
tar -czf /PATH/TO/BACKUP/jahannama-media.tar.gz \
  -C /opt/Jahannama media
```

پوشه مقصد باید خارج از مسیرهای نمونه و مطابق سیاست نگهداری پشتیبان انتخاب شود.

پشتیبان‌گیری زمانی قابل اعتماد است که بازیابی آن نیز عملاً آزمایش شده باشد.
